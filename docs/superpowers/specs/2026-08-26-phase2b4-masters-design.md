# 薬局業務日誌 フェーズ2b-4：マスタ設定 設計書

作成日: 2026-08-26

## 1. 背景と目的

フェーズ2b-1で閲覧、2b-2で編集、2b-3で月報ができるようになった。フェーズ2b-4では、医師名・予製品目・チェックリスト項目・記入者を編集できるマスタ設定画面を追加する。

全体設計は [DB化・Web化 設計書](2026-08-25-pharmacy-log-db-migration-design.md) の 6.1「マスタ設定」に基づく。これでフェーズ2b(Web画面)の主要機能が揃う。

- **フェーズ2b-1**: 日誌一覧・詳細(閲覧のみ) — 完了
- **フェーズ2b-2**: 日誌詳細の編集・保存 — 完了
- **フェーズ2b-3**: 月報 — 完了
- **フェーズ2b-4**: マスタ設定(本設計書) — 次はここ

### 非目的 (YAGNI)

- **並び順の変更(上下移動)は対象外。** 既存アプリの予製マスタ・医師マスタには上下移動ボタンがあるが、現在のWebアプリ(2b-1〜2b-3)はどこもマスタの並び順を参照していない(2b-2の編集は各日の既存データの並び、2b-3の集計は件数順ソート)。追加順のまま保持する
- **新規記入者へのデフォルトチェックリストの複製は対象外。** 既存アプリは新規記入者に対しハードコードされた6項目のチェックリストを複製するが、この文言をアプリのコードに埋め込むのは避け、空のチェックリストから始めてユーザーが追加する方式にする
- **重複登録のチェックは対象外。** 既存アプリも重複チェックをしておらず、同名の登録を許容している

## 2. アーキテクチャ

```
src/app/storage.js         … Storage.getMasters() を追加(読み取り専用)
src/app/views/masters.js   … マスタ設定画面の描画とフォーム収集
src/app/main.js            … 「データ管理」パネルを開いたときにマスタを読み込み、保存を仲介する
```

**`Storage.getMasters(): Promise<object>`** — `masters/current` ドキュメントを読み取り、`{members: string[], checklist: object, premixes: string[], doctors: string[]}` を返す。ドキュメントが存在しない場合は空の初期値を返す(既存の `saveMasters` が書き込むフィールドと対になる読み取り専用の関数)。

**`MastersView.render(container, masters, onSave)`** — 4セクション(記入者管理・チェックリスト編集・予製マスタ・医師マスタ)を**常時編集可能な状態**で描画する。フェーズ2b-2の詳細画面のような「閲覧⇔編集」の切り替えは無い(設定パネルは開いたら常に編集できる)。「保存」ボタンクリックで、その時点の状態を1つのオブジェクトにまとめて `onSave(data)` を呼ぶ。

リストの追加・削除UIは、フェーズ2b-2の `edit.js` で確立した「テーブル行+削除ボタン、イベント委譲による行追加」パターンを踏襲する(既存アプリの生の `<span>` タグではなく、このアプリで既に統一されているスタイルに合わせる)。

## 3. 画面構成

| セクション | 操作 |
|---|---|
| 記入者管理 | 一覧表示、末尾に追加、削除(最低1名は残す) |
| チェックリスト編集 | 記入者を選ぶドロップダウンで対象を切り替え、その記入者のチェック項目を追加・削除する |
| 予製マスタ | 一覧表示、末尾に追加、削除 |
| 医師マスタ | 一覧表示、末尾に追加、削除 |

チェックリストは記入者ごとに個別の配列(`masters.checklist[記入者名]`)を持つため、画面には常に1人分だけを表示する。ドロップダウンで記入者を切り替えても、他の記入者に対して行った未保存の変更はメモリ上に保持されたまま失われない(実際にFirestoreへ書き込まれるのは「保存」を押したときのみ)。記入者を削除しても、その人のチェックリストデータ自体は `checklist` オブジェクトに残る(既存アプリと同じ挙動。実害の無い孤立データとして許容する)。

記入者が1人もいない状態(初回・未移行時)では、チェックリスト編集セクションはドロップダウンの代わりに「記入者を追加してください」という案内を表示する。

## 4. データフロー

1. 詳細画面のような別画面ではなく、既存の「データ管理」折りたたみパネル(`#toolsDetails`)に3枚目のカードとして追加する
2. パネルを初めて開いたとき、既存の `refreshStatus()` と同じタイミングで `Storage.getMasters()` を呼び、`MastersView.render()` で描画する(既存の `statusLoaded` と同じ「初回のみ読み込む」ガードに乗せる)
3. 「保存」を押すと、その時点の記入者・チェックリスト・予製・医師をまとめて `Storage.saveMasters(data)`(既存関数、変更不要)で書き込む
4. 保存成功・失敗をボタン付近に一言で表示する(成功: 「保存しました」、失敗: エラーメッセージ)。保存後も画面は同じ状態を保持し、再読み込みは行わない(表示中の内容がそのまま保存された内容のため)

## 5. エラー処理

- マスタの取得(`getMasters`)に失敗した場合は、カード内にエラーメッセージを表示する
- 保存(`saveMasters`)に失敗した場合は、保存ボタン付近にエラーメッセージを表示し、入力内容は保持したまま再度「保存」を押せるようにする
- 記入者を1名まで減らそうとした場合は保存前に弾き、既存アプリと同じ「最低1名必要です」の趣旨のメッセージを表示する

## 6. テスト方針

- `src/app/views/masters.js` は `list.js` / `detail.js` / `edit.js` と同様、DOM組み立てコードのため自動テストを持たない。目視確認(実機・開発サーバ)で検証する
- `Storage.getMasters()` は `listLogsByMonth` / `saveLog` と同様、薄いFirestoreラッパーのため自動テストを持たない
- 新規に切り出す純粋なロジック(集計や日付計算のような)は無いため、今回のフェーズにNode単体テストの追加は無い
