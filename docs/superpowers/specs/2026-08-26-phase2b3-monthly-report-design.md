# 薬局業務日誌 フェーズ2b-3：月報 設計書

作成日: 2026-08-26

## 1. 背景と目的

フェーズ2b-1で月別一覧・日誌詳細の閲覧、フェーズ2b-2で日誌詳細の編集ができるようになった。フェーズ2b-3では、既存アプリ(`pharmacy_logV2.6.html`)にある月報機能をFirestoreベースのWebアプリへ移植する。

全体設計は [DB化・Web化 設計書](2026-08-25-pharmacy-log-db-migration-design.md) の 6.1「月報」に基づく。フェーズ2bはさらに以下へ分割して進める。

- **フェーズ2b-1**: 日誌一覧・詳細(閲覧のみ) — 完了
- **フェーズ2b-2**: 日誌詳細の編集・保存 — 完了
- **フェーズ2b-3**: 月報(本設計書) — 次はここ
- **フェーズ2b-4以降**: マスタ設定(医師名・予製品目・チェックリスト項目・記入者の編集)

### 非目的 (YAGNI)

- **「部門長会議報告書」は対象外。** `pharmacy_logV2.6.html`には月報とは別に年度単位(4月始まり)の集計タブがあるが、現行の設計書の画面一覧には含まれておらず、今回は移植しない。必要になれば別途フェーズを立てる
- **マスタの編集は対象外。** 月報は医師マスタ・予製マスタを**読み取り専用**で参照する(疑義照会医師別集計・予製薬剤別集計で、実績が0件の医師・薬剤も行として表示するため)。マスタの追加・削除・並べ替えはフェーズ2b-4で扱う
- **グラフ描画ライブラリは追加しない。** 既存アプリの「日別処方箋件数」は棒グラフだが、CSS(`width:%`のdiv)で実装されており、これを踏襲する。依存パッケージを追加しない方針に合致する

## 2. アーキテクチャ

既存の`list.js`/`detail.js`/`edit.js`は「描画」と「フォーム収集」のみを担うDOM組み立てコードで、自動テストを持たない。月報は性質が異なり、**多数の集計計算(合計・グルーピング・曜日別・週別など)が中心**で、DOMに依存しない純粋なロジックとして切り出せる。既存アプリの`renderMonthly()`は集計とHTML生成が1関数(600行超)に混在しており、これをそのまま移植すると同じ問題を持ち込むことになる。

そこで、集計とレンダリングを分離する。

```
src/model/monthly-report.js   … 集計ロジック(純粋関数、DOMに触れない)
src/app/views/report.js       … 描画(集計済みデータをHTMLにするだけ)
src/app/storage.js            … Storage.getMasters() を追加(読み取り専用)
src/app/main.js               … 「月報」⇔「一覧」の画面切り替え
```

**`MonthlyReport.compute(entries, ym, masters)`** — その月の日誌配列(`Storage.listLogsByMonth`の戻り値そのまま)とマスタ(`Storage.getMasters()`の戻り値)から、月報表示に必要な集計済みのプレーンオブジェクトを返す。`src/model/holidays.js`・`src/model/month.js`と同じ場所・同じ流儀(依存パッケージなし、Node/ブラウザ両対応)に置く。

**`ReportView.render(container, report)`** — `compute()`の戻り値だけを見てHTMLを組み立てる。`list.js`/`detail.js`と同じIIFEパターン。

この分離により、**集計ロジックにNode単体テストを書ける**(3節参照)。このプロジェクトは「取込ロジックが誤るとデータが静かに壊れる」という理由でパーサーを最重要のテスト対象としてきたが、月報の集計も同じ性質(計算を間違えても画面上は「それらしい数字」が出るだけで気づきにくい)を持つため、同じ扱いとする。

## 3. 集計ロジック (`MonthlyReport.compute`)

既存`renderMonthly()`にある集計を、意味のまとまりごとに分けて算出する。

| 集計 | 内容 | 出典(既存関数内の変数) |
|---|---|---|
| 概要統計 | 外来処方箋・外来注射箋・病棟注射箋・服薬指導・疑義照会・持参薬鑑別・持参薬1包化・病棟処方箋の月間合計、入力日数、病棟定期/病棟処方箋の日平均 | `totalOpCnt`ほか |
| 処方箋受付 区分別合計 | 外来処方箋・外来注射箋・病棟注射箋の枚数/件数と合計 | 同上 |
| 日別処方箋件数 | 日ごとの外来処方箋+外来注射箋の合計(棒グラフ用、最大値に対する割合も算出) | `maxRx` |
| 疑義照会 区分別 | `INQ_TYPES`ごとの件数、処方変更率 | `inqByType`, `changeRate` |
| 疑義照会 医師別 | 医師マスタの全医師を0件から並べ、実績を集計。マスタに無い医師名や「医師未選択」も別枠で集計 | `inqByDoctor`, `inqUnassigned` |
| 処方変更 医師別(日次入力) | `doctorChanges`フィールドの医師別合計 | `docChangeByDoctor` |
| 欠品 薬剤別 | `shortages`フィールドの薬品別合計数量 | `shortagesByDrug` |
| 持参薬鑑別・1包化 病棟別 | `DailyLog.wardMedsFrom`で算出した4病棟(かりゆし/ゆいゆい/うりずん北/はいさい)の合計 | `wardByName` |
| 予製 薬剤別 | 予製マスタの全品目を0件から並べ、実績を集計。マスタ外品目も別枠で集計 | `premixByDrug` |
| 病棟処方箋 病棟別×区分別 | 5病棟×(定期/臨時/退院/持参薬/合計)の`cnt`合計 | `wardRxByName` |
| 曜日別集計 | 曜日ごとの外来注射箋・病棟注射箋・病棟定期/臨時/退院/合計・入力日数・定期平均・病棟平均 | `dowT` |
| 週別詳細 | 週ごとの日別明細(日付・曜日・外来処方・外来注射・服薬指導・疑義照会・持参薬・病棟処方) | `weeks` |
| 分包機メンテ月間集計 | 分包紙・インクの合計数、清掃の実施回数(錠剤/散剤別) | `packerCount` |
| 会議 種別集計 | `MEETING_TYPES`ごとの回数と開催日一覧 | `meetingByType` |
| MR訪問 | 月内の全件を日付付きで一覧化 | — |
| 問い合わせ 区分別 | `CONTACT_FROM`ごとの件数 | `contactByFrom` |
| 研修会 | 月内の全件を日付付きで一覧化、参加人数合計 | `allTrainings` |
| 記入者別集計 | 記入者ごとの入力日数と入力日一覧 | `byAuthor` |

`compute()`は上記を1つのオブジェクトにまとめて返す。各項目のキー名・フィールド名は実装計画で確定する。

**マスタが存在しない場合**(`masters`ドキュメントが未作成、または医師・予製リストが空)は、医師別・薬剤別集計のうち「マスタの全件を0件から並べる」処理を単純にスキップし、実績のある医師・薬剤のみを表示する。エラーにはしない。

## 4. 画面構成・データフロー

- ツールバーに1つのボタンを追加する。一覧表示中は「月報」、月報表示中は「一覧」とラベルが変わり、クリックで表示を切り替える
- 月移動(◀/▶/今月)は、現在の表示(一覧 or 月報)を維持したまま該当月のデータを再読み込みする。月報を見ている間に月を移動しても、一覧表示に戻らない
- 月報表示時は、その月の日誌(`Storage.listLogsByMonth`、既に一覧取得で使っているものを再利用)に加えて`Storage.getMasters()`でマスタを取得し、`MonthlyReport.compute()` → `ReportView.render()`の順に処理する
- マスタ取得も非同期のFirestore読み取りのため、フェーズ2b-1(月移動)・フェーズ2b-2(保存)で導入したリクエスト連番ガードと同じ考え方を月報側にも適用し、月を連続で切り替えたときに古い集計結果が新しい月の画面に表示される事故を防ぐ

## 5. エラー処理

- 日誌の取得(`listLogsByMonth`)に失敗した場合は、既存の一覧画面と同じ扱い(エラーメッセージを表示)とする
- マスタの取得(`getMasters`)に失敗した場合は、月報エリアにエラーメッセージを表示し、集計・描画は行わない
- その月の日誌が1件もない場合は「この月のデータがありません」という空状態を表示する(既存アプリと同じ)

## 6. テスト方針

- **`src/model/monthly-report.js`は自動テストを書く。** `tests/monthly-report.test.js`に、`tests/daily-log.test.js`と同じ形式(Node標準`assert`、依存パッケージなし)で、2〜3日分の合成データに対して主要な集計(合計、曜日別、医師別のマスタ0件補完と未選択集計、処方変更率、空月の扱い)を検証する
- **`src/app/views/report.js`は自動テストを持たない。** `list.js`/`detail.js`/`edit.js`と同様、DOM組み立てコードのため目視確認(実機・開発サーバ)で検証する
- **`Storage.getMasters()`は自動テストを持たない。** `listLogsByMonth`/`saveLog`と同様、薄いFirestoreラッパーのため
