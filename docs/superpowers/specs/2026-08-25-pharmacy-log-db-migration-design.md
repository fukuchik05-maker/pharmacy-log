# 薬局業務日誌 DB化・Web化 設計書

作成日: 2026-08-25

## 1. 背景と目的

### 現状

薬局業務日誌は単一HTMLファイル `C:\Users\GM\Desktop\業務日誌\pharmacy_logV2.6.html` で運用している。
データベースを持たず、蓄積CSV (`pharmacy_accum_YYYY-MM-DD.csv`) を読み込んで画面上で編集し、
再びCSVとして書き出す完全クライアント完結型である。

そのため以下の制約がある。

- 特定のPCでしか入力・閲覧できない
- 外出先やスマートフォンから参照できない
- 蓄積CSVを手動で管理する必要がある

### 目的

1. データをクラウドDB (Firestore) に移し、恒久的に保存する
2. どの端末からでも Web ブラウザで閲覧・修正できるようにする
3. 日々のデータ取込を自動化し、手作業を減らす

### 非目的 (YAGNI)

- 複数人での同時利用。閲覧・入力は本人のみ
- 勤怠管理カレンダー (kin プロジェクト) との統合。**別プロジェクトとする**
  - 業務ドメインが重ならず、共有すべきエンティティが存在しないため

## 2. 全体構成

```
[利用者]
   │  (1) 病院システムが出力する日次CSV を置く
   │  (2) Excelテンプレートに手入力して置く
   ↓
Dropbox /アプリ/薬局業務日誌/
   ├── 取込待ち/     ← (1)(2) を置く場所
   ├── 処理済み/     ← 取込成功したファイルの退避先 (年月別)
   └── エラー/       ← 取込失敗したファイルの退避先
   ↑
   │  (3) 毎日定刻に参照 (PC電源不要)
   │
[GitHub Actions]  cron 起動の Node 製取込スクリプト
   │
   │  (4) パースして書き込み
   ↓
[Firestore]  日誌データ / マスタ / 取込ログ
   ↑
   │  (5) 読み書き
   │
[GitHub Pages]  Webアプリ (Googleログインで本人のみ)
```

### 技術選定と根拠

| 要素 | 採用技術 | 根拠 |
|---|---|---|
| ファイル保管 | Dropbox (アプリ用フォルダ) | 既存の運用を変えずに済む。アプリ用フォルダ権限によりトークンの権限範囲を当該フォルダ内に限定できる。リフレッシュトークンに有効期限がなく保守不要 |
| 定期実行 | GitHub Actions (cron) | 無料。PC電源不要。ワークフロー定義もスクリプトも同一リポジトリで管理でき、Git履歴に残る |
| DB | Cloud Firestore | Firebase Spark (無料) の枠内で十分。1日1ドキュメントの規模に対し無料枠は読取5万/日・書込2万/日と桁違いに余裕がある |
| 認証 | Firebase Authentication (Google) | 無料。本人のアカウントのみ許可する |
| ホスティング | GitHub Pages | 無料。kin プロジェクトと同じ運用 |

**Cloud Functions は採用しない。** Blaze プラン (従量課金・クレジットカード登録必須) への切り替えが必要になるため。
定期実行を GitHub Actions が担うことで、構成全体を Spark プラン (無料・カード登録不要) に収める。

## 3. 入力ファイル仕様

日次で 2 種類のファイルを `取込待ち/` に置く。**いずれも 1 日 1 ファイル**とする。

### 3.1 病院システム出力CSV

- ファイル名: `MMDD.csv` (例 `0824.csv`)
- **文字コード: Shift-JIS (CP932)**
- ヘッダーが 2 行構成 (1行目=処方区分、2行目=枚数/件数)
- 最終行と最終列に合計行・合計列を含む

```
病棟,入院定期,,入院臨時,,退院,,持参薬,,1包化　持参薬,,■合計■,
,処方箋枚数,調剤件数,処方箋枚数,調剤件数,...
かりゆし,16,61,22,22,0,0,0,0,0,0,38,83
...
■合計■,45,184,59,62,0,0,3,11,0,0,107,257
```

このファイルが更新するのは **`wardRx` (病棟別処方箋データ) のみ**。

### 3.2 Excelテンプレート (手入力分)

- ファイル名: `MMDD.xlsx` (例 `0824.xlsx`)
- Webアプリの「テンプレートをダウンロード」機能で生成する。対象日を指定でき、既定は翌営業日とする。
  ファイル名・日付・記入者・各マスタが記入済みの状態で出力されるため、コピーやリネームの手作業は不要

#### シート1「日誌」— 形が毎日一定の項目

| 区分 | 項目 |
|---|---|
| 基本 | 日付、記入者 |
| 外来 | 内服外用処方箋 (枚/件)、注射処方箋 (枚/件)、薬剤管理指導業務 (件) |
| 病棟別 | 注射 (枚数/件数) × 5病棟 |
| 処方変更 | 医師別件数 (マスタの9名) |
| 予製 | 品目別包数 (マスタの9品目) + その他 |
| 分包機 | 錠剤・散剤それぞれ 分包紙 / インク / 清掃 |
| 提出資料 | DIニュース (有無)、薬局からのお知らせ (件数)、その他 (自由記述) |
| チェックリスト | マスタの項目ごとに実施チェック |
| その他 | 自由記述 |

- チェック欄はプルダウン (`✓` / 空) とし、入力ゆれを防ぐ
- 数値セルには入力規則を設定し、文字列の混入を防ぐ

**持参薬鑑別・1包化は本シートに含めない。** 病院システムCSVの「持参薬」「1包化　持参薬」列から取得できるため
(蓄積CSV 97日分・387件の突き合わせで完全一致を確認済み)。

#### シート2「明細」— 発生した日だけ記入する項目

種別列で束ねた単一の表とし、行数は可変。

| 種別 | 対象 | 区分 | 内容 | 数量 |
|---|---|---|---|---|
| 疑義照会 | 井手 慎子 | 用量 | (処方内容) | |
| 来客 | 東和 | | 12月追補品 | |
| 薬品管理 | | 採用 | (薬品名) | |

- 種別 (プルダウン): 疑義照会 / 来客 / 問い合わせ / 薬品管理 / 欠品 / 会議 / 研修
- 区分は種別に応じた選択肢を提示する
- 空行は無視する。記入事項が無い日はシートを空のままでよい

## 4. データ構造 (Firestore)

### 4.1 `dailyLogs` コレクション

ドキュメントID = `YYYY-MM-DD` (例 `2026-08-24`)。
**フィールド名は現行の蓄積CSVと同一**とする。過去データ移行をそのまま通すため。

| フィールド | 由来 | 内容 |
|---|---|---|
| `date`, `author` | Excel | 日付、記入者 |
| `wardRx[]` | **病院CSV** | 病棟別 定期/臨時/退院/持参薬/1包化/合計 (枚数・件数) |
| `rxOpCnt`, `rxOpDose` | Excel | 内服外用処方箋 枚/件 |
| `rxInjCnt`, `rxInjDose` | Excel | 注射処方箋 枚/件 |
| `counsel` | Excel | 薬剤管理指導業務 |
| `winjData[]` | Excel | 注射 (病棟別) |
| `doctorChanges[]` | Excel | 処方変更 (医師別件数) |
| `premixes[]` | Excel | 予製 (品目・包数) |
| `packerData` | Excel | 分包機メンテ (錠剤/散剤) |
| `submissions` | Excel | 提出資料 **(新規)** |
| `checklist[]` | Excel | チェックリスト実施記録 **(新規)** |
| `inquiries[]` | Excel明細 | 疑義照会 |
| `mrVisits[]` | Excel明細 | 来客 |
| `contacts[]` | Excel明細 | 問い合わせ |
| `drugs[]` | Excel明細 | 薬品管理 |
| `shortages[]` | Excel明細 | 欠品 |
| `meetings[]` | Excel明細 | 会議 |
| `trainings[]` | Excel明細 | 研修参加 |
| `notes` | Excel | その他 |
| `_meta` | 自動 | 取込元・更新日時 (`csvIngestedAt` / `xlsxIngestedAt` / `webEditedAt`) |

Excel「明細」シートは取込時に種別ごとの配列へ振り分ける。集計を容易にするため。

**`wardMeds` (持参薬鑑別・1包化) は保存しない。** `wardRx` から表示時に算出する。
二重に保存するとデータが乖離しうるため。

### 4.2 `masters` コレクション

医師名 / 予製品目 / チェックリスト項目 / 記入者。
現行の蓄積CSV末尾のコメント行 (`#DOCTOR_MASTER` 等) から移行する。
Webアプリから編集でき、変更内容は翌日以降のExcelテンプレート生成に反映される。

### 4.3 `ingestRuns` コレクション

取込の実行結果を1実行1ドキュメントで記録する。Webアプリのダッシュボードに表示する。

- 実行日時、対象ファイル、成功/失敗、エラー詳細 (ファイル名・シート名・行番号・理由)

## 5. 取込処理

### 5.1 処理フロー

1. `取込待ち/` のファイル一覧を取得
2. ファイル名から日付と種別 (CSV / Excel) を判定
3. パースして該当日付のドキュメントへ書き込み
   - 病院CSV → `wardRx` のみ更新
   - Excel → 手入力項目のみ更新
   - **両者は更新領域が排他であり、投入順序に依存しない**
4. 成功 → `処理済み/YYYY-MM/` へ移動
5. 失敗 → `エラー/` へ移動し、失敗理由を併置
6. 実行結果を `ingestRuns` に記録

### 5.2 設計上の決定事項

- **文字コード**: 病院CSVは Shift-JIS として明示的にデコードする
- **部分成功を許容**: 病院CSVが成功しExcelが失敗した日は、CSV由来のデータのみ反映する
- **二重取込の防止**: 成功したファイルは移動されるため、同一ファイルが再度読まれることはない
- **訂正時の扱い**: 同一日付の新しいファイルが置かれた場合はその内容で上書きする (新規ファイルの投入 = 意図的な訂正とみなす)
- **年の判定**: ファイル名は `MMDD` のみのため、実行日から見て最も近い年を採用する

### 5.3 パーサーの共有

パーサーと検証ロジックは**独立したJavaScriptモジュール**として実装し、
GitHub Actions 側 (Node) と Webアプリ側 (ブラウザ) の**双方から同一コードを利用**する。
実装が二重化して挙動が乖離することを防ぐため。

## 6. Webアプリ

現行 `pharmacy_logV2.6.html` の画面構成・操作感を踏襲して移植する。

### 6.1 画面一覧

| 画面 | 内容 |
|---|---|
| ダッシュボード | 取込状況パネル、今月の主要数値、「今すぐ取込」、「テンプレートをダウンロード」 |
| 日誌一覧 | 日付順リスト。出どころバッジ (CSV / Excel / Web修正)、月切替、祝日・欠損日の色分け |
| 日誌詳細・編集 | 1日分の全項目表示と、その場での修正・保存 |
| 月報 | 現行の月報機能を踏襲 (病棟別集計、医師別処方変更、疑義照会の区分別、グラフ) |
| マスタ設定 | 医師名・予製品目・チェックリスト項目・記入者の編集 |

### 6.2 取込状況パネル

- 最新の実行結果 (成功件数 / エラー内容)
- 取込履歴 (展開表示)
- **未処理ファイルの警告**: `取込待ち/` に残存するファイルがある場合に表示
- **データ欠損の警告**: 記録の無い平日を指摘する。
  kin プロジェクトの `holidays.js` (`C:\Users\GM\Desktop\csv\kin\holidays.js`) を流用し、祝日・振替休日を除外して誤検知を防ぐ

### 6.3 「今すぐ取込」の実現方式

**ブラウザ内で直接パースする方式を採用する。**

ボタン押下でファイル選択ダイアログを開き、選択されたファイルをブラウザ上で解析して
Firestore へ直接書き込む。Dropbox および GitHub Actions を経由しない。

- 即時に反映される (数秒)
- **権限キーをページに一切埋め込まない**
- 取込前に画面上で検証エラーを提示できる
- スマートフォンからも利用できる

代替案として「ボタンから GitHub Actions を起動する」方式を検討したが、採用しない。
GitHub Pages は公開ページであり、起動用の権限キーを安全に置けない。
DB経由で起動要求を渡す間接方式では GitHub Actions の cron 最短間隔 (5分、混雑時は15分程度の遅延)
に律速され、「即時」の要件を満たせないため。

## 7. セキュリティ

本データには**疑義照会の患者IDおよび薬剤情報が含まれる**。以下を厳守する。

| 対象 | 保管場所 | 保護方法 |
|---|---|---|
| 日誌データ | Firestore のみ | セキュリティルールにより、本人のアカウントで認証された場合のみ読み書きを許可。他は全拒否 |
| CSV / Excel 実ファイル | Dropbox のみ | **Gitリポジトリには一切置かない**。`.gitignore` で機械的に排除する |
| Dropbox トークン | GitHub Secrets | クライアントに露出させない。権限範囲はアプリ用フォルダ内に限定 |
| Firebase サービスアカウント鍵 | GitHub Secrets | 同上 |

GitHub Pages を無料で使うためリポジトリは公開となるが、これは許容する。
保護の主体はコードの秘匿ではなく Firestore のセキュリティルールであり、
未認証のアクセスはデータに到達できない。
(クライアントコードに含まれる Firebase `apiKey` は秘密鍵ではなくプロジェクト識別子であり、公開が前提の値である)

**「コードは公開、データは非公開」** の状態を維持する。

## 8. 過去データの移行

現行の蓄積CSV `pharmacy_accum_2026-08-24.csv` に **2026-04-01 〜 2026-08-24 の 97 日分**が存在する。
これを Firestore へ一括投入する。

- Firestore のフィールド名を蓄積CSVと揃えているため、変換は素直に行える
- マスタ (`#MEMBERS` / `#CHECKLIST` / `#PREMIX_MASTER` / `#DOCTOR_MASTER`) も併せて移行する
- 移行は一度きりの実行とする

なお 97 日分のうち平日で記録の無い日は 7 日あり、うち 6 日は祝日 (4/29, 5/4, 5/5, 5/6, 7/20, 8/11)、
残る 8/7 は祝日ではない。祝日判定を入れることで、欠損警告が実用的な精度になることを裏づけている。

## 9. テスト方針

取込ロジックが誤ると**データが静かに壊れる**ため、パーサーを最重要のテスト対象とする。

- パーサーは独立モジュールとし、単体テストを書く
- テストデータは実ファイルに基づくが、**患者情報を含まないダミーに差し替えたもの**をリポジトリに置く
- 検証項目
  - Shift-JIS の読み込み
  - 2段ヘッダーの解釈
  - 合計行・合計列の除外
  - 空行の無視
  - ファイル名からの日付判定 (年またぎを含む)
  - 不正データが確実にエラーとなること
- 過去データ移行スクリプトは、**97日分の変換結果が元CSVと完全一致すること**を検証する
- kin プロジェクトと同じく、依存パッケージなしで `node tests/xxx.test.js` により実行できる形とする

## 10. 実装方針

kin プロジェクトの既存の流儀に合わせる。

- 依存パッケージを持たない素の JavaScript
- Node 標準の `assert` によるテスト
- 機能単位でのファイル分割
