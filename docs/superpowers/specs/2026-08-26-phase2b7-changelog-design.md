## 1. 背景と目的

既存アプリ(`pharmacy_logV2.6.html`)には「更新履歴」タブがあり、バージョン・日付・種別(機能追加/バグ修正)・変更内容・原因を一覧表示していた。「完全移植」の方針で今回追加するが、**旧アプリの履歴データそのものは移植しない**。

旧アプリの履歴は単一HTMLファイル・多段階入力フロー(STEP0担当者選択など)という、今のFirestoreベースのWebアプリには存在しない仕組みを説明する内容だったため、参照価値が無い。代わりに、**この新しいWebアプリ自身の開発履歴**を、フェーズ1から今後にわたって記録していく。

- **フェーズ2b-1〜2b-6**: 完了
- **フェーズ2b-5**: 他部署向け日報 — 保留中
- **フェーズ2b-7**: 更新履歴(本設計書) — 次はここ

### 非目的 (YAGNI)

- **旧アプリ(`pharmacy_logV2.6.html`)の履歴データは移植しない**
- **Firestoreへの保存はしない。** 開発者(このセッションの私)が各フェーズ完了時にコードへ1件追記する、既存アプリと同じ「配列に追記するだけ」の運用とする
- **タブや専用ボタンは新設しない。** 既存の「データ管理」折りたたみパネルにカードとして追加する

## 3. アーキテクチャ

`src/app/views/changelog.js`(新規)1ファイルに、静的な履歴配列と描画関数をまとめる。集計や状態管理が無い単純な内容のため、他のビューのような「集計/描画の分離」は不要。

```javascript
var CHANGELOG_ENTRIES = [
  { date: "2026-08-26", type: "feat", title: "...", detail: "...", cause: null },
  ...
];

function render(container) { ... }

root.ChangelogView = { render: render };
```

`type` は `feat`(機能追加)・`fix`(バグ修正)・`chore`(調整)の3種類とし、旧アプリと同じ配色のバッジで表示する。`cause`(原因)はバグ修正エントリにのみ設定し、無い場合は表示しない。

## 4. 画面

既存の「データ管理」折りたたみパネルに、マスタ設定の下に4枚目のカードとして追加する。パネルを開いたときに(既存の`refreshStatus`/`loadMasters`と同じタイミングで)描画する。Firestore読み取りが無いため、非同期処理は不要で即座に描画できる。

## 5. 今後の運用

新しいフェーズが完了するたびに、`CHANGELOG_ENTRIES` 配列の先頭に1件追加する。既存アプリと同じ「配列に足すだけ」の運用とする。
