# モバイル入力ページの数値入力を打ちやすく(フェーズ3-4) 設計書

作成日: 2026-08-27

## 1. 背景と目的

モバイル入力ページ(`entry.html` / `src/entry/entry-form.js`)の数値入力欄は、すべて
`value="0"` で初期化されている。スマートフォンで入力するとき、欄をタップするとカーソルが
「0」の前後に来るため、まず「0」を選択して消してから数字を打つ操作が必要で、これが
50以上ある全欄で発生する。実用上かなり煩わしい。

### 目的

- 数値入力欄を**空欄 + プレースホルダ「0」**にして、タップしたらそのまま打てるようにする。
- `inputmode="numeric"` を付けて、スマホで **0〜9 だけのテンキー**が出るようにする
  (現状 `type="number"` でも数字キーボードは出るが、機種により小数点や記号が混ざる)。

### 非目的 (YAGNI)

- 編集画面(`src/app/views/edit.js`)の変更。既存値が入っている場面が多く、優先度が低い。
  今回はモバイル入力ページのみ。
- `type="number"` を `type="text"` へ変えること。`type="number"` は維持し、`inputmode` を足すだけ。
- スピナー(上下の矢印)の非表示化などの見た目調整。
- `collect()` / 合計計算ロジックの変更。

## 2. 対象と変更内容

**対象ファイル**: `src/entry/entry-form.js` のみ。

すべての数値入力を生成している箇所で、次の2点を行う:

1. `value="0"` を**削除**し、代わりに `placeholder="0"` を付ける。
2. `inputmode="numeric"` を付ける。

対象の生成箇所:

| 箇所 | 内容 |
|---|---|
| `numInput(field, value)` ヘルパー | 外来処方箋・外来注射箋(枚/件)、薬剤管理指導 |
| `winjBody()` のインライン input | 病棟別注射 5病棟 × 枚/件 |
| `wardRxKindBlock(kind)` のインライン input | 病棟別処方箋 5区分 × 5病棟 × 枚/件 |
| `doctorChangesBody(masters)` の input | 処方変更 医師別件数 |
| `premixesBody(masters)` の input | 予製 品目別包数 |
| `packerBody()` の input | 分包機 分包紙・インク(錠剤/散剤) |
| `fieldInputHtml(spec, value)` の `type === "number"` 分岐 | 明細の数量(欠品)・参加人数(研修会) |

`fieldInputHtml` の `number` 分岐は現在 `value="' + num(value) + '"` としている。新規行では
`value` が `undefined` → `num(undefined)` = 0 → `value="0"` になる。ここも `value` を出さず
`placeholder="0"` にする(明細行は毎回新規なので既存値の考慮は不要)。

## 3. 挙動

- **空欄の表示**: 入力欄は空で、薄いグレーで「0」がプレースホルダ表示される。数値としては
  未入力(`input.value === ""`)。
- **タップ**: 空欄なのでカーソルが入るだけ。すぐ数字を打てる。`inputmode="numeric"` により
  0〜9 のテンキーが出る。
- **収集(`collect()`)**: 既存の `num()` は `Number("")` が `0` を返すため、`num("")` → 0。
  未入力欄は従来どおり 0 として `payload` に入る。**`collect()` は変更しない。**
- **合計の自動計算**: `render()` 内の `input` リスナーが各欄の `.value` を `num()` に通して
  合計している。空欄は 0 とみなされるため、合計ブロックは初期状態で「0 / 0」、入力に応じて
  更新される。**リスナーは変更しない。**
- **記入者・日付**: `#entryAuthor`(select)・`#entryDate`(`type="date"`)は数値入力ではない
  ため対象外。

## 4. エラー処理

変更なし。数値でない文字が入っても `num()` が 0 に落とす(既存の全数値入力と同じ)。
`type="number"` のため通常は数字以外を打てない。

## 5. テスト方針

`entry-form.js` は DOM 組み立てファイルのため自動テストを持たない(既存方針)。
ブラウザで手動確認する:

- モバイル入力ページを開き、`wardRx` セクションを ON にする。
- 数値入力欄が**空欄**で、プレースホルダ「0」がグレー表示されていること。
- 欄をタップして数字を打つと、0 を消す操作なしにそのまま入ること。
  (実機/モバイルエミュレーションで、テンキーが出ることも確認)
- どの欄も触らずに記入者だけ選んで「下書きを送信」→ 承認 → 対象日の詳細で、
  未入力だった項目が 0 として入っていること(合計も含めて破綻しない)。
- いずれかの欄に値を入れ、同じ病棟の合計ブロックが更新されること。

## 6. プロジェクト全体の絶対原則(再確認)

- 依存パッケージを一切追加しない。
- `dailyLogs` への書き込みは Google 認証済みの本人のみ(このページは匿名で `draftEntries` のみ)。
- Firebase Spark プラン(無料)を維持。
